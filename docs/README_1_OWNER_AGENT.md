# Ноутбук 1 — твой основной аккаунт: агент и интеграция

## Контекст

Мы на HackAlem, решаем Beeline Tariff Marketing Campaigns. Старый проект про сеть заменён. Нужно сделать Agent.act(env), который анализирует 23 441 абонента, делает пилоты и возвращает 1–10 кампаний «сегмент → тариф → канал». Максимизируем дополнительную выручку минус расходы. Лимиты: 100 000 у.е., 15 000 контактов вместе с пилотами, 5000 на кампанию, 20 пилотов по 10–200 человек. История не совпадает с целевой выборкой; пилоты шумные.

Это твой первый из двух ноутбуков. Второй аккаунт улучшает research/, напарник на третьем делает проверки и демонстрацию. Ты владелец итоговой сборки.

## Твоя зона

`agent.py`, `strategy/`, `requirements.txt`, `.env.example`, корневые README/STATUS/AGENTS, `docs/API_CONTRACT.md`, итоговый `submission.csv`. Свой README тоже обновляешь. Не переписывать research/, tools/, demo/ и тесты напарника без необходимости и согласования.

## Задачи по приоритету

1. Сохранить работающий baseline. Улучшить выбор пилотов: сначала несколько гипотез, затем дополнительные наблюдения для перспективных/неуверенных вариантов. Все размеры и решения соблюдать по остаткам env.
2. Обоснованно учитывать неопределённость и сравнивать каналы по чистому эффекту. Результат пилота уже включает канал. Не превращать исторические частоты переходов в вероятность отклика кампании.
3. Планировать финальные кампании с учётом пересечений, повторных пилотных контактов, бюджета, охвата и порядка. Оставлять допустимый результат при плохой серии наблюдений.
4. Согласовать и подключить улучшенный build_candidates с ноутбука 2 без изменения его входов/выходов в одиночку.
5. При наличии времени добавить ограниченный LLM-компонент для выбора гипотез/объяснений. Это опционально. OPENAI_API_KEY только из окружения, модель доступная аккаунту, таймауты/ограничение вызовов/fallback. Проверить официальную документацию перед кодированием. Базовая сдача воспроизводима без сети; не предполагать детерминированность LLM.
6. Принять проверенные PR ноутбуков 2 и 3, заново прогнать проверки и сгенерировать submission.csv. Проверить упаковку импортируемых strategy/research у организаторов.

Кредиты OpenAI и NVIDIA/Brev есть по словам владельца, баланс/назначение не подтверждены. Не публиковать ссылки активации и секреты, не запускать платную инфраструктуру автоматически. GPU этой базе не нужен.

## Готово, когда

- local_eval.py без ошибок/отброшенных кампаний; 1–10 финальных кампаний, пилотов >0;
- 10 seed проверены, реальные результаты и ограничения записаны;
- make_submission.py повторно даёт одинаковый файл;
- unittest проходит, все исходные файлы организатора неизменны;
- README объясняет подход и запуск, нет выдуманных результатов LLM;
- в итоговый репозиторий вошли изменения всех трёх ноутбуков.
