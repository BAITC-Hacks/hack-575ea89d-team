## Как устроены решения и ограничения

1. До 12 начальных гипотез в порядке research. Размер растёт как квадратный корень отношения ARPU сегмента к медианному ARPU первых гипотез, в пределах 80–200; ресурсные остатки могут уменьшить его до 10. Исторические частоты не используются как конверсия.
2. Рабочая ошибка: `sqrt(max(1, observed_repeat_variance) / n)`. Это консервативная эвристика, **не калиброванный доверительный интервал** и не поправка на множественный отбор. Повтор выбирается для неопределённого знака/конкуренции; на одну пару не планируется повтор после достижения 400 суммарных наблюдений (последний пакет может пересечь 400).
3. Другой канал проверяется прямым пилотом. Публичные множители задают только оптимистичную оценку полезности проверки с учётом насыщения; итоговый эффект не переносится с одного канала на другой.
4. Остановка: нет доступного действия с потенциальной пользой выше расходов, альтернативной стоимости контактов и 1% текущей оценки плана; либо исчерпаны ресурсные/пилотные пределы. Это приближённая ценность информации, не точный байесовский расчёт.
5. Финальная оценка `mean * n/(n+20)` — слабое нейтральное сжатие. Четыре жадных распределения с разной ценой ресурсов сравниваются по дополнительной ожидаемой чистой выручке. Глобальная оптимальность не гарантирована. Порядок выбранных кампаний строится по текущей предельной пользе; весь план заранее помещается в остатки.
6. ID пилотных контактов недоступны. Используется верхнее приближение ожидаемого положительного эффекта уже охваченной доли аудитории, ограниченное лучшей наблюдаемой оценкой. Для неоднородных сегментов/повторных подвыборок оно неточно. Отрицательные пилоты не «отменяются» планировщиком.
7. До 3000 пилотных контактов и до 20% начального бюджета; резерв текущего финального плана. На маленьком остатке первый пилот может выйти за добровольный лимит разведки, сохранив физические лимиты и одну финальную кампанию. При полном отказе API возвращается пустой список: обещать валидный измеренный план в этом случае невозможно.
8. research отвечает за допустимые сегменты; аудитории вне 10–5000 не обрезаются. Контракт build_candidates v1 не изменён. LLM, секретов и новой платной инфраструктуры нет.
