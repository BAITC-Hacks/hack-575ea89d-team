# Текущее состояние проекта

Обновлено: 2026-09-23. Основная ветка для команды: `main` после переноса каркаса; исходная рабочая ветка каркаса: `codex/mvp-skeleton`.

## Что сделано

- Создан общий README, API-контракт и правило передачи контекста между сессиями.
- Подготовлен FastAPI backend с маршрутами `GET /health`, `/towers`, `/incidents`, `/incidents/{id}`, `/work-orders/{id}` и `POST /analyze`, `/simulate`, `/action`.
- Реализован цикл OpenAI Responses function calling: чтение жалоб, вышек, сети, инцидентов, расчёт решения, подтверждение команды и приоритета. В отсутствие ключа используется явно помеченный demo-режим с теми же Python-инструментами.
- Изменения инцидентов и work orders сохраняются в локальную SQLite.
- Локально проверен сервисный demo-путь: найден `INC-1042`, выполнены 6 инструментов, при бюджете 20 млн ₸ доступны варианты 12/18 млн ₸, создан и прочитан `WO-8821`. Цикл function calling отдельно проверен с подставным клиентом; реальный OpenAI API не вызывался.
- OpenAI вызовы ограничены общим бюджетом 35 секунд при 45-секундном ожидании frontend. Отдельно проверен путь таймаута: возвращается `demo_fallback` и запись об ошибке.
- Добавлены минимальные синтетические fixtures для вышек, инцидентов и вариантов решения.
- Добавлена папка frontend с инструкцией по интеграции.
- Абыл добавил воспроизводимый генератор 4 200 жалоб, 35 вышек и населения 12 районов; Tower #17, #23, #31 и #8 имеют специальные сценарии.
- В сервисе данных появились фильтрация жалоб, чтение населения и поиск ближайшей вышки; демо-кластер фильтруется по стабильному `demo_age_minutes`.
- Временная формула симуляции заменена оценкой нагрузки после увеличения ёмкости и числа пользователей, которым может помочь ёмкость/покрытие. Формула и допущения записаны в `docs/API_CONTRACT.md`.

## Что сейчас является заглушкой

- Путь с реальным OpenAI API ещё не проверен с ключом и моделью команды; при ошибке ответа API backend переключается в `demo_fallback` и сообщает об этом в `agent_mode` и журнале.
- В окружении предыдущей backend-сессии не было `OPENAI_API_KEY` и `OPENAI_MODEL`; FastAPI/OpenAI пакеты не установлены, а установка из сети недоступна. Поэтому HTTP-сервер здесь не запущен. Frontend Манса проверен им с настоящим FastAPI в отдельном окружении и находится в PR #2.
- Новый набор проверен на уровне сервисов в отдельной копии; полный совместный HTTP/UI-прогон остаётся следующим шагом.
- Эффект симуляции остаётся грубой оценкой: географическое перекрытие зоны покрытия и аудитории не моделируется.
- Локальная SQLite обеспечивает хранение на одном backend-хосте; это демонстрационное состояние, не общая база команды.
- Dashboard реализован в ветке `codex/mans-dashboard`, PR #2; актуальная проверка описана ниже.

## Decision Studio и реальная карта Астаны — 2026-09-23

В «Карте и сети» встроена настоящая карта улиц и зданий Астаны: Leaflet 1.9.4 и тайлы OpenStreetMap, масштабирование, перемещение, выбор вышки и кнопка «Все вышки». Координаты и инциденты читаются из API. География реальная, вышки и прогнозы синтетические; линии сети и зоны покрытия не выдумываются. Для CDN и подложки нужен интернет, ключ карты не нужен. Атрибуция OSM видна на карте. При недоступности библиотеки автоматически показана локальная схема; при ошибке тайлов есть сообщение и ручное переключение на схему.

«Пульт решений» сравнивает стоимость и прогноз нагрузки на интерактивном графике, показывает границу бюджета, приоритеты цены/нагрузки/срока и попарные различия. Недоступный вариант можно изучить, но нельзя подтвердить. При изменении бюджета старый расчёт скрывается. Заказ создаётся только отдельным подтверждением пользователя.

Изменения подготовлены к публикации по явному запросу пользователя в codex/mans-dashboard / PR #2. Включён main 6de9d59 с данными и расчётами Абыла; его backend, JSON, контракт и личная документация сохранены. Конфликт STATUS разрешён с сохранением записей обеих сторон.

Проверки: синтаксис JS, 12 регрессионных тестов; в браузере загружаются реальные улицы, работают масштабирование и переключение карты/схемы. Decision Studio ранее проверен на desktop и 390 px. В отдельной копии backend с новыми сервисами и заново сгенерированным набором 35 вышек / 4200 жалоб выполнен сервисный demo-анализ INC-1042, симуляция upgrade (12 млн, 71%, 600 пользователей), создание и чтение WO-8821. Это сервисная проверка нового набора, не полный HTTP/UI-прогон на 35 вышках. Открытый локальный предпросмотр использует прежние 4 вышки. Реальный OpenAI не вызывался.
