# Текущее состояние проекта

Обновлено: 2026-09-23. Основная ветка для команды: `main` после переноса каркаса; исходная рабочая ветка каркаса: `codex/mvp-skeleton`.

## Что сделано

- Создан общий README, API-контракт и правило передачи контекста между сессиями.
- Подготовлен FastAPI backend с маршрутами `GET /health`, `/towers`, `/incidents`, `/incidents/{id}`, `/work-orders/{id}` и `POST /analyze`, `/simulate`, `/action`.
- Реализован цикл OpenAI Responses function calling: чтение жалоб, вышек, сети, инцидентов, расчёт решения, подтверждение команды и приоритета. В отсутствие ключа используется явно помеченный demo-режим с теми же Python-инструментами.
- Изменения инцидентов и work orders сохраняются в локальную SQLite.
- Локально проверен сервисный demo-путь: найден `INC-1042`, выполнены 6 инструментов, при бюджете 20 млн ₸ доступны варианты 12/18 млн ₸, создан и прочитан `WO-8821`. Цикл function calling отдельно проверен с подставным клиентом; реальный OpenAI API не вызывался.
- OpenAI вызовы ограничены общим бюджетом 35 секунд при 45-секундном ожидании frontend. Отдельно проверен путь таймаута: возвращается `demo_fallback` и запись об ошибке.
- Добавлены минимальные синтетические fixtures для вышек, инцидентов и вариантов решения.
- Добавлена папка frontend с инструкцией по интеграции.

## Что сейчас является заглушкой

- Путь с реальным OpenAI API ещё не проверен с ключом и моделью команды; при ошибке ответа API backend переключается в `demo_fallback` и сообщает об этом в `agent_mode` и журнале.
- В текущем рабочем окружении нет `OPENAI_API_KEY` и `OPENAI_MODEL`; FastAPI/OpenAI пакеты не установлены, а установка из сети недоступна. Поэтому HTTP-сервер здесь не запущен. Frontend Манса проверен им с настоящим FastAPI в отдельном окружении и находится в PR #2.
- `complaints.json` и `population.json` пусты; 3–5 тысяч жалоб и 30–50 вышек ещё не подготовлены.
- Симуляция использует временную формулу; Абыл должен уточнить её и допущения.
- Локальная SQLite обеспечивает хранение на одном backend-хосте; это демонстрационное состояние, не общая база команды.
- Dashboard реализован в PR #2; на Brev развёрнута зафиксированная версия 81469b6, в main frontend пока не перенесён.
