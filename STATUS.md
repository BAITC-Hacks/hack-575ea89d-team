# Текущее состояние проекта

Обновлено: 2026-09-23. Основная ветка для команды: `main` после переноса каркаса; исходная рабочая ветка каркаса: `codex/mvp-skeleton`.

## Что сделано

- Создан общий README, API-контракт и правило передачи контекста между сессиями.
- Подготовлен FastAPI backend с маршрутами `GET /health`, `/towers`, `/incidents`, `/incidents/{id}`, `/work-orders/{id}` и `POST /analyze`, `/simulate`, `/action`.
- Реализован цикл OpenAI Responses function calling: чтение жалоб, вышек, сети, инцидентов, расчёт решения, подтверждение команды и приоритета. В отсутствие ключа используется явно помеченный demo-режим с теми же Python-инструментами.
- Изменения инцидентов и work orders сохраняются в локальную SQLite.
- Локально проверен сервисный demo-путь: найден `INC-1042`, выполнены 6 инструментов, при бюджете 20 млн ₸ доступны варианты 12/18 млн ₸, создан и прочитан `WO-8821`. Цикл function calling отдельно проверен с подставным клиентом; реальный OpenAI API не вызывался.
- OpenAI вызовы ограничены общим бюджетом 35 секунд при 45-секундном ожидании frontend. Отдельно проверен путь таймаута: возвращается `demo_fallback` и запись об ошибке.
- Добавлены минимальные синтетические fixtures для вышек, инцидентов и вариантов решения.
- Frontend Манса реализован в ветке `codex/mans-dashboard`, PR #2: три шага, фильтры, сравнение, бюджет и создание заказа; проверен с настоящим FastAPI.

## Что сейчас является заглушкой

- Путь с реальным OpenAI API ещё не проверен с ключом и моделью команды; при ошибке ответа API backend переключается в `demo_fallback` и сообщает об этом в `agent_mode` и журнале.
- По записи Рамазана, в его рабочем окружении нет `OPENAI_API_KEY` и `OPENAI_MODEL`; FastAPI/OpenAI пакеты не установлены, а установка из сети недоступна. Поэтому HTTP-сервер здесь не запущен. Frontend Манса проверен им с настоящим FastAPI в отдельном окружении и находится в PR #2.
- `complaints.json` и `population.json` пусты; 3–5 тысяч жалоб и 30–50 вышек ещё не подготовлены.
- Симуляция использует временную формулу; Абыл должен уточнить её и допущения.
- Локальная SQLite обеспечивает хранение на одном backend-хосте; это демонстрационное состояние, не общая база команды.
- Dashboard доступен в PR #2, пока не объединён с main. История нагрузки и жизненный цикл заказа требуют новых данных/API; в интерфейсе не имитируются.

Географическая карта выбранной вышки открывается отдельной вкладкой OpenStreetMap; схема всех вышек остаётся доступной без внешней подложки. Для OSM нужен интернет, координаты передаются этому сервису только при переходе. Покрытие и топология не выдумываются.
- В сравнении показаны самые дешёвые, быстрые и дающие минимальную прогнозную нагрузку варианты только среди доступных в бюджете. При равенстве показателей перечислены все подходящие решения; нет рейтинга AI-уверенности.
- Бюджет, поиск, четыре фильтра и выбранный инцидент сохраняются в localStorage отдельно для каждого API. Адрес API тоже восстанавливается после перезагрузки. Недействительные фильтры сбрасываются; повреждённое/запрещённое хранилище не ломает dashboard. Решение, подтверждение и результаты симуляции не восстанавливаются: выполняется новый расчёт.
- Прямые ссылки `?incident=INC-1042` и копирование ссылки. URL имеет приоритет над сохранённым выбором; неизвестный ID показывает сообщение, а не чужой инцидент. Коллеге нужны доступный ему адрес frontend и тот же backend; localhost-ссылка работает только на текущем компьютере.
- Индикатор API отражает последний запрос; время загрузки сети — время получения `/towers` и `/incidents` браузером, не время измерения нагрузки. Через 5 минут предлагается обновить данные. Фоновый опрос и повторы `/action` не добавлены.
