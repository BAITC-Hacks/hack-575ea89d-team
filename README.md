# Network Intelligence Agent

Демонстрация: жалобы → инцидент → Python-диагностика и AI-инструменты → сравнение решений → бюджет → подтверждение человека → сохранённый Work Order. Данные и прогнозы синтетические.

## Запуск для всей команды

Нужен Python 3.11+ с venv. Из **корня репозитория**:

```sh
python run.py
```

На Linux/macOS при необходимости используйте `python3`. При первом запуске создаётся `backend/.venv` и устанавливаются зависимости (нужен интернет). Затем откройте **http://127.0.0.1:8000/** — это dashboard. **http://127.0.0.1:8000/docs** — техническая документация API, экран со списком GET/POST; это не ошибка frontend.

Отдельный запуск frontend, Node.js и npm не нужны. Backend отдаёт интерфейс и API по одному адресу. Если 8000 занят: `python run.py --port 8001` и откройте напечатанный адрес.

В репозитории уже находятся данные Абыла: **35 вышек, 4200 жалоб, население 12 районов**. Генерировать или скачивать их при обычном запуске не нужно. `python run.py` использует `backend/data/` и сохраняет заказы в `backend/data/state.sqlite3`. `--no-ai` принудительно включает Python-demo независимо от ключа. Синтетические жалобы с `demo_age_minutes` сохраняют повторяемое окно сценария.

Для доступа в доверенной локальной сети: `python run.py --host 0.0.0.0`, затем IP компьютера и порт 8000; интерфейс автоматически использует тот же сервер. Публичная аутентификация не реализована.

## OpenAI

Скопируйте `backend/.env.example` в `backend/.env`. Для скрытого ввода ключа используйте Python из созданного окружения:

```sh
# Linux/macOS
backend/.venv/bin/python deploy/brev/configure-openai.py
# Windows
backend\.venv\Scripts\python.exe deploy/brev/configure-openai.py
```

Перезапустите приложение. Ключ и модель задаются только на backend. Без них режим `demo`; при ошибке провайдера — `demo_fallback` с явной записью в журнале. Настоящий AI засчитывается только после:

```sh
backend/.venv/bin/python deploy/brev/verify-ai.py --require-openai
```

Реальный OpenAI пока не подтверждён: на проверенном сервере ключ и модель не заданы. Модельный анализ ограничен 35 секундами, интерфейс ждёт 45 секунд. Метрики, приоритет, назначение команды и расчёты проверяет Python.

## Что исправлено в интеграции

- Dashboard Манса включён в общую ветку; главная страница работает с тем же API и на другом компьютере.
- Анализ сохраняет выбранный инцидент, проверяет область, доказательства, команду, приоритет и JSON модели.
- Повторные и одновременные подтверждения одного pending-заказа возвращают существующий ID. Доступен список заказов выбранного инцидента.
- Создание инцидента по кластеру защищено от одновременных дублей; будущие жалобы не попадают в прошлое окно.
- Подключены опубликованные данные и расчёты Абыла; допущения расчётов описаны в [DEMO_MODEL.md](docs/DEMO_MODEL.md).

## Проверки

```sh
python -m pip install -r backend/requirements-dev.txt
python -m pytest backend/tests -q
node --test frontend/tests/dashboard.test.cjs
```

Backend-тесты используют временные SQLite и подставной клиент OpenAI; не вызывают платный API. Frontend-тесты проверяют состояние и запросы, а не внешний вид. GitHub Actions запускает оба набора. Windows-запуск поддержан кодом, но должен быть отдельно проверен на Windows.
