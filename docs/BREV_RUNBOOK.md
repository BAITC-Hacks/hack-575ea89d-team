## OpenAI: главный оставшийся блокер

На сервере проверено только наличие значений (не сами значения): OPENAI_API_KEY=False, OPENAI_MODEL=False. backend/.env создан из примера, права 600. Настоящего запроса к OpenAI НЕ было. Идентификатор из ссылки проекта не является API-ключом. Баланс Brev не оплачивает OpenAI API.

Подготовлены и уже переданы на сервер:

- deploy/brev/install-services.sh — создаёт systemd-сервисы; реально выполнен успешно, bash -n пройден. Не меняет существующий .env.
- deploy/brev/configure-openai.py — интерактивно спрашивает ключ скрытым вводом и ID модели, сохраняет в backend/.env с правами 600; остальные переменные сохраняются. Требует терминал, не выводит ключ. По умолчанию предлагает gpt-4.1-mini, существующий ID модели сохраняет. Скрипт пока НЕ выполнялся с настоящим ключом.
- deploy/brev/verify-ai.py — POST /analyze, выводит режим, ID инцидента и инструментальные шаги. С --require-openai завершится ошибкой при demo/demo_fallback. Пока НЕ выполнен с реальным OpenAI.

Пользователь должен сам ввести ключ в своём SSH-терминале:

```bash
cd /home/ubuntu/workspace/hack-575ea89d-team
backend/.venv/bin/python deploy/brev/configure-openai.py
sudo systemctl restart network-intelligence-api
backend/.venv/bin/python deploy/brev/verify-ai.py --require-openai
```

Доступность модели для аккаунта и API-биллинг не проверены. Документация подтверждает Responses и function calling у gpt-4.1-mini: https://developers.openai.com/api/docs/models/gpt-4.1-mini . Использован навык openai-docs, прочитана https://developers.openai.com/api/docs/guides/function-calling . Не считать успешный fallback проверкой AI.
