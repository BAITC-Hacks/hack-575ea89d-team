## История и ранжирование

История покрывает 168 из 420 возможных направленных пар разных тарифов;
36 пар содержат меньше 20 сырых записей. В 2118 записях ARPU до смены
меньше 100, включая 1407 с неположительным значением. У положительных
знаменателей медиана относительного изменения 1,40%, 95-й перцентиль
936,20%, максимум 592 276 в долях. Малые знаменатели дают экстремальные
отношения, поэтому необработанное среднее ненадёжно.

Среди записей с определимым отношением 6115 имеют изменение выше +10%,
5707 ниже −10%. Это распределение среди сменивших тариф, не доли откликов
на кампанию. Нет ни контрольной группы, ни числа получателей предложений.
Даже положительный prior не доказывает причинный эффект.

`build_candidates(profile, tariffs, history_path=None)` сохраняет контракт v1:

1. Удаляет только полностью идентичные события при наличии ID_NUMBER и TIME_KEY.
   Одинаковые значения ARPU у разных событий остаются отдельными наблюдениями.
2. Берёт конечные неотрицательные значения ARPU после и ARPU до ≥100.
   Исторические группы: тариф-источник, ARPU до смены, тариф-назначение.
   Границы baseline сохранены: 1000 относится к MID, 5000 — HIGH.
   В тексте руководства порог 5000 описан неоднозначно; профиль не пересчитывается.
3. Ограничивает отношения диапазоном [−1, 3], берёт медиану и сжимает её:
   `prior_lift_ratio = median × n / (n + 20)`.
   `history_support` — число допустимых записей после удаления точных копий.
   Медиана оценивает типичную смену, а не математическое ожидание выручки.
4. Вычисляет fit как среднее доступных показателей покрытия медианного
   DATA_VOLUME, медианных OUT_LOC_OFFNET_MIN и доступности цены относительно
   медианного predicted_arpu. Каждый показатель ограничен [0,1].
   Из двух голосовых пакетов берёт максимум, а не сумму.
   Не включает on-net минуты в пакет off-net. При отсутствии признаков fit=0,5.
5. `priority = max(prior, 0) × sum(predicted_arpu) × (0.8 + 0.2 × fit)`.
   Если истории пары нет, prior=0 и support=0, а для priority используется
   исследовательский сигнал 0,01 вместо max(prior,0). Это условный приоритет
   разведки, не 1% ожидаемого эффекта. Отрицательную историю не превращаем
   в положительный prior. Коэффициенты — эвристики, не калибровка на mock.
6. Сначала предлагает лучший вариант каждой ячейки, потом второй вариант.
   Priority сравним внутри прохода; весь список не обязан убывать, так как
   разнообразие ячеек важнее второго предложения той же аудитории.
7. Ячейки >5000 рекурсивно делятся data_segment, затем call_segment.
   Возвращаются только непересекающиеся листья 10–5000. Если разрешённых
   фильтров недостаточно, лист пропускается, без усечения по ID. Подгруппы
   наследуют историческую оценку родителя: потребления в истории смен нет.

Функция не меняет входы, не вызывает сеть/пилоты/LLM. Пустая или отсутствующая
история допустима; неправильная схема выдаёт понятную ошибку. Отсутствующие
необязательные параметры тарифа нейтральны. Невалидный predicted_arpu исключает
всю соответствующую ячейку: удалять отдельные строки нельзя, поскольку фильтр
кампании всё равно выбрал бы их. Каналы, бюджет и итоговый выбор — зона planner.

## Восемь гипотез для пилотов

Числа рассчитаны по текущим данным и доступны в first_eight файла audit.json.
Prior указан после сжатия. Он может превышать 100% и не является вероятностью.
Размер — вся выбранная аудитория, не рекомендованный размер пилота.

| Текущий тариф / ARPU | Целевой | Аудитория | Support | Prior | Медиана МБ | Цена целевого |
|---|---|---:|---:|---:|---:|---:|
| tariff_4 / MID | tariff_9 | 1227 | 11 | 41,12% | 621,83 | 4364,60 |
| tariff_8 / MID | tariff_10 | 1720 | 182 | 28,62% | 1139,75 | 7504,60 |
| tariff_8 / LOW | tariff_9 | 457 | 26 | 169,57% | 258,69 | 4364,60 |
| tariff_13 / MID | tariff_8 | 1022 | 234 | 37,35% | 5,27 | 5934,60 |
| tariff_11 / HIGH | tariff_12 | 1633 | 107 | 10,16% | 3995,58 | 12 528,60 |
| tariff_4 / LOW | tariff_9 | 299 | 17 | 137,84% | 247,32 | 4364,60 |
| tariff_10 / MID | tariff_11 | 645 | 86 | 36,83% | 2053,06 | 9388,60 |
| tariff_11 / LOW | tariff_8 | 387 | 16 | 85,30% | 618,00 | 5934,60 |

1. tariff_4/MID → tariff_9: положительное историческое изменение при цене
   ниже исходной цены tariff_4 (4678,60). Проверить знак совокупного эффекта:
   support=11 слишком мал для уверенного масштабирования.
2. tariff_8/MID → tariff_10: большая аудитория и support=182. Проверить,
   сохраняется ли эффект при более дорогом пакете; медианный трафик заметно
   меньше пакета целевого тарифа 12 288 МБ.
3. tariff_8/LOW → tariff_9: высокий prior связан с низкой исходной выручкой
   и ограничением отношения сверху. Проверить, не исчезает ли рост после
   включения неоткликнувшихся абонентов в пилот.
4. tariff_13/MID → tariff_8: относительно много истории, но всего 5,27 МБ
   медианного потребления. Проверить полезность предложения интернет-пакета
   8192 МБ; история сама по себе не доказывает потребность.
5. tariff_11/HIGH → tariff_12: prior скромнее, но база predicted_arpu
   составляет 14 175 708,00. Проверить абсолютный эффект и риск удорожания
   до 12 528,60 при медианном потреблении 3995,58 МБ.
6. tariff_4/LOW → tariff_9: support=17 и prior выше 100%.
   Проверить воспроизводимость положительного наблюдения до масштабирования.
7. tariff_10/MID → tariff_11: support=86, пакет 20 480 МБ при медиане
   потребления 2053,06 МБ. Проверить, оправдывает ли эффект более высокую цену.
8. tariff_11/LOW → tariff_8: предложение дешевле исходного тарифа 9388,60.
   Проверить риск снижения выручки, несмотря на исторический положительный
   prior; support=16 и переносимость истории ограничены.

Размер пилота и повторные проверки определяет ноутбук 1. Ни одна гипотеза
не должна становиться финальной кампанией только на основании этой таблицы.
Сравнение каналов требует отдельных наблюдений; prior не содержит конверсию.

## Проверки и фактическое сравнение

Python 3.12.14, pandas 2.3.3, numpy 2.5.3, Windows.
Парный benchmark использует один и тот же неизменённый planner и официальный
local_eval для обеих версий. Baseline candidates взят из 7c2257c; код baseline
не менялся при слиянии PR #4. Все результаты — mock, не оценка скрытого судейства.
Полные значения по seed, затраты и время: [mock_comparison.json](../research/mock_comparison.json).

| Метрика, seed 0–9 | Baseline | Research |
|---|---:|---:|
| Минимум net | 1 882 072 | 2 230 914 |
| Медиана net | 3 178 575 | 2 532 686 |
| Максимум net | 3 727 614 | 2 682 466 |
| Положительные прогоны | 10/10 | 10/10 |

Research выше baseline в 2 из 10 парных прогонов. Медиана хуже: данную
версию нельзя представлять как доказанное улучшение результата. Более высокий
минимум десяти seed также не доказывает меньший риск на скрытой среде.
Медиана исторических изменений устойчивее к единичному выбросу, но теряет
информацию о правом хвосте, значимую для суммарной выручки.

Seed 42: net 2 120 877, 12 пилотов и 8 финальных кампаний,
24 640 затрат и 6160 контактов вместе с пилотами. Baseline net 2 519 731.
Официальные local_eval.py и local_eval.py --runs 10 выполнены.

Девять research-тестов проверяют отсутствие мутации, детерминизм/перестановку
входов, редкую/пустую историю, точные дубликаты, выброс, отрицательный эффект,
границы ARPU, валидность фильтров и разбиение крупной аудитории.
В изолированной копии после генерации submission прошли все 17 тестов,
включая SHA256 материалов организаторов и ограничения кампаний.

Обычный запуск полной suite в рабочей Windows-копии выявил два ограничения:

- Git core.autocrlf=true преобразовал 14 файлов организаторов в CRLF,
  поэтому побайтовая проверка SHA256 не прошла. В проверочной копии восстановлены
  оригинальные Git blobs; все hashes совпали. Исходные файлы в PR не меняются.
- Сохранённый submission относится к baseline. Его должен пересоздать ноутбук 1
  после интеграции. Кроме этого, существующий тест сравнивает pandas.to_csv()
  с read_text(): на Windows первый использует CRLF, второй нормализует LF.
  Для изолированной suite использован os.linesep="\n" в тестовом процессе,
  чтобы воспроизвести Linux-конвенцию. Чужой тест не редактировался.

Для повторения на Linux или checkout с исходными LF:

```bash
python -m research.audit > research/audit.json
git show 7c2257cf53fb045148ac3652c1f68abbe8216415:research/candidates.py > /tmp/baseline_candidates.py
python tests/test_research_benchmark.py --baseline /tmp/baseline_candidates.py --output research/mock_comparison.json
python -m unittest discover -s tests -p 'test_research*.py' -v
python local_eval.py
python local_eval.py --runs 10
# Только в отдельной проверочной копии или при интеграции ноутбуком 1:
python make_submission.py
python -m unittest discover -s tests -v
```

На Windows для полной suite в проверочной копии с исходными байтами:
`python -c "import os,runpy,sys; os.linesep=chr(10); sys.argv=['unittest','discover','-s','tests','-v']; runpy.run_module('unittest',run_name='__main__')"`.
Сначала выполните make_submission.py в той же копии.
