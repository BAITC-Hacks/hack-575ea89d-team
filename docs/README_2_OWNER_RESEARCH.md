# Ноутбук 2 — твой другой аккаунт: данные и гипотезы

## Контекст

Ты работаешь на втором ноутбуке того же владельца. Основной ноутбук пишет агента и собирает проект, напарник делает проверки/демо. Репозиторий BAITC-Hacks/hack-575ea89d-team теперь решает кейс Beeline Tariff Marketing Campaigns, а не старую задачу про вышки.

Нужно выбирать прибыльные тарифные кампании для 23 441 абонента. Агент проверяет гипотезы шумными пилотами, затем возвращает 1–10 кампаний. 100 000 у.е. и 15 000 контактов включают пилоты; 5000 абонентов на кампанию; 20 пилотов по 10–200. История описывает другую выборку. Твоя роль — предложить хорошие гипотезы для тестирования, а не угадать скрытые ответы.

## Конкретные задачи

1. Разобрать customer_profile, историю смен тарифов, traffic, arpu_monthly, справочники. Проверить ключи, пропуски, дубликаты, распределение размеров сегментов, наличие истории по парам тарифов. Исходные данные не менять.
2. Улучшить `build_candidates(profile, tariffs, history_path=None) -> list[dict]` по контракту. Использовать историю, текущую ценность/размер аудитории, потребление и параметры тарифов. Не вызывать env.run_pilot: это зона ноутбука 1.
3. Учитывать малые исторические выборки, выбросы и отсутствие истории. Не тратить все гипотезы на один сегмент. Подумать о разбиении сегментов >5000 разрешёнными data/call-фильтрами.
4. Явно разделять историческое изменение ARPU среди перешедших и ожидаемый эффект кампании. История смен не даёт знаменатель для вероятности отклика.
5. В docs/RESEARCH.md записать 5–10 обоснованных гипотез, способ ранжирования, ограничения и что агент должен проверить пилотами. Все числа вычислять из данных.
6. Проверить детерминизм, отсутствие изменения входных DataFrame, валидность тарифов/фильтров, непустые сегменты и корректность на редкой/отсутствующей истории. Сравнить local_eval до/после на тех же seed, пометить результаты как mock.

Ни LLM, ни GPU для этой части не обязательны. Не активировать кредиты и не вшивать ссылки на купоны/ключи. Не подгонять код к внутренней таблице мока.

Важные ограничения: история не пересекается с целевой аудиторией; support — события среди сменивших тариф, не получатели предложений. В месячной выручке неоднозначные дубли ID–месяц; LTE-трафик противоречит общему. Исторический prior и priority не являются ожидаемой прибылью. На реальных CSV нет ячеек >5000; ветка разбиения проверена синтетически.
