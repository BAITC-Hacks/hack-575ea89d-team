# Beeline Tariff Campaign Agent

Проект команды для HackAlem: агент исследует аудиторию, проверяет предложения пилотами и возвращает до 10 тарифных маркетинговых кампаний. Цель — максимальный прирост выручки за вычетом расходов на коммуникации. Все данные синтетические, суммы — условные единицы.

Старый Network Intelligence Agent (вышки, жалобы, карта, work orders) удалён из текущего проекта. Его код доступен в истории Git до перехода, исходный main: `3a524b5`. Старые ветки и PR #1/#3 не являются основой нового кейса; не объединяйте их целиком в новый main.

Основная версия нового проекта — `main`. Переход со старого проекта: [PR #4](https://github.com/BAITC-Hacks/hack-575ea89d-team/pull/4). Создавайте рабочие ветки трёх ноутбуков от `origin/main`.

## Запуск

Нужен Python 3.12 (проверено на 3.12). Все команды выполняются из корня репозитория.

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
python -m unittest discover -s tests -v
```

Если в вашей системе команда называется `python3`, используйте её при создании окружения. Основной агент работает без API-ключей и без интернета после установки зависимостей. Отчёт для просмотра: `python tools/report.py --seed 42`; он создаёт `artifacts/report.json`.

## Что уже работает

`agent.py` вызывает `strategy/planner.py`; интерфейс `research.candidates.build_candidates` не изменён. История задаёт порядок гипотез, но не подменяет измерения конверсии. Первые пилоты покрывают до 12 гипотез; размер 80–200 зависит от объёма ARPU сегмента и доступных ресурсов. Затем агент выбирает повторный замер спорного варианта или прямой пилот другого канала. Общий предел — 20 пилотов, до 3000 контактов и 20% начального бюджета разведки; текущий финальный план резервируется перед каждым пилотом. При малом остатке допускается один первый пилот с резервом хотя бы одной финальной кампании.

Итоговые кампании используют только проверенные пары «тариф–канал». Наблюдения усредняются с весом размера пилота, ожидаемый эффект слегка сжимается к нулю (20 условных нейтральных наблюдений). Неопределённость направляет повторные замеры; она не является обязательным порогом статистической значимости для финального выбора. Планировщик сравнивает четыре жадных распределения бюджета/контактов по дополнительной чистой выручке. Пересечения добавляют только улучшение эффекта, но полностью расходуют контакты и бюджет. Уже полученный эффект пилотов приближённо учитывается по доле охваченного сегмента: публичный API не раскрывает ID участников пилотов.

На seed 0–9 медиана +3 724 743 против +3 178 575 у исходного baseline, улучшение в 10/10 парах. Независимая контрольная серия seed 20–29 также улучшилась в 10/10 парах. Это результаты учебной среды, не гарантия скрытого результата. В [журнале проверки](docs/AGENT_VALIDATION.md) сохранены также две неудачные версии, ограничения метода и команды. Дополнительные независимые проверки планировщика: `python -m unittest strategy.test_planner -v`.

Агент работает без LLM и сети. При плохих наблюдениях возвращает допустимый проверенный вариант с наименьшим ожидаемым убытком; прибыль не гарантируется. Если публичный API не позволяет провести ни одного пилота, корректный проверенный план построить невозможно. Крупные сегменты должен разбивать research разрешёнными фильтрами; планировщик не обрезает аудиторию произвольно. Формат сдачи модульного агента остаётся открытым вопросом организаторам.

## Правила кейса

- 23 441 абонент, 21 тариф; бюджет 100 000 у.е.
- 1–10 итоговых кампаний; до 5000 абонентов на кампанию.
- До 15 000 контактов суммарно с пилотами; до 20 пилотов по 10–200 человек.
- Push: 0; SMS: 4; digital_ads: 22; call: 160 у.е. за контакт.
- Один абонент приносит эффект только один раз; повторные контакты расходуют лимиты.
- История — другая выборка. Пилоты обязательны, их результаты должны менять решения.
- Локальные эффекты отличаются от скрытых судейских: локальный плюс не обещает финальный балл.
- Нельзя извлекать скрытые эффекты через внутренности среды. Выданные средства оценки не менять.
- По ТЗ лимит выполнения 10 минут. В комментарии шаблона указаны 5 минут и отсутствие интернета; до ответа организаторов целимся в <5 минут и сохраняем автономный режим. LLM по основному ТЗ разрешена.

## Что сдавать

Обязательно `agent.py`, сгенерированный `submission.csv`, необходимые зависимости. Наша реализация модульная: приложите также `strategy/`, `research/` и используемый `data/change_tariff.csv` (они уже в репозитории). Не отправляйте один `agent.py` без импортируемых модулей. Формат упаковки дополнительных файлов уточните у организаторов; при требовании одного файла ноутбук 1 должен собрать автономный `agent.py` и повторить проверки.

README и воспроизводимость дают 25/100 баллов по присланной таблице. Остальные: работоспособность 25, техническая реализация 25, ценность 15, оригинальность и развитие 10. Таблица организаторов сохранена в [дополнении](docs/JUDGING.md).

## Кредиты и инфраструктура

У команды заявлены OpenAI API credits и NVIDIA/Brev credits. Они отдельны от виртуальных 100 000 у.е. в задаче. Текущий агент их не расходует. Ссылки активации, купоны и ключи в Git не добавлять. Доступность и баланс не проверялись, кредиты не активировались этой сессией.

Ноутбук 1 отвечает за необязательную интеграцию OpenAI: ключ только из `OPENAI_API_KEY`, модель из `OPENAI_MODEL`, ограниченные время и число вызовов, обработка ошибок и рабочая логика без модели. `.env.example` — образец; `.env` автоматически не читается. Перед интеграцией проверяйте актуальную официальную документацию и доступные аккаунту модели. Повторяемая сдача не должна зависеть от случайного ответа LLM.

Brev можно рассмотреть для общего демонстрационного окружения позже. Не считать купон Brev автоматически токенами NVIDIA NIM: назначение и доступные услуги нужно проверить в кабинете. Для текущего объёма данных GPU не требуется. Запуск платных ресурсов — отдельное решение команды после проверки условий.
