# Контекст для любого нового агента

Текущий кейс: **Beeline Tariff Marketing Campaigns**. Репозиторий `BAITC-Hacks/hack-575ea89d-team`. Старый проект про вышки/инциденты завершён и удалён из рабочей версии. Не восстанавливать старый backend/frontend или PR #1/#3.

## Сначала прочитать

1. `STATUS.md`, `README.md`, `PARTICIPANT_GUIDE.md`.
2. `docs/API_CONTRACT.md`.
3. Инструкцию своего ноутбука: `docs/README_1_OWNER_AGENT.md`, `docs/README_2_OWNER_RESEARCH.md` или `docs/README_3_PARTNER_DEMO.md`.
4. Проверить ветку, `git status` и актуальный `origin/main` — основу нового проекта. Не затирать локальную чужую работу.

## Ответственность

- Ноутбук 1: `agent.py`, `strategy/`, общий README/STATUS/контракт/requirements, финальный `submission.csv`, интеграция.
- Ноутбук 2: `research/`, `tests/test_research*.py`, свой README и `docs/RESEARCH.md`.
- Ноутбук 3: `tools/`, `demo/`, `tests/test_contract*.py`, `tests/test_agent*.py`, свой README, `docs/VALIDATION.md`, `docs/PITCH.md`.
- Менять интерфейс соседнего модуля только после согласования через контракт/PR. Каждый обновляет свой README со статусом, проверками и следующим шагом; общий STATUS сводит ноутбук 1. Не просить разрешения на обычные изменения в своей зоне.
- Каждый ноутбук работает в собственной ветке; PR направлять в main. Только ноутбук 1 объединяет работы и генерирует итоговый submission. Не force-push и не reset чужих изменений.

## Ограничения агента

Вход: публичный env. Выход: 1–10 корректных кампаний. Обязательны реальные вызовы env.run_pilot и влияние наблюдений на решения. 100000 у.е., 15000 контактов вместе с пилотами, 5000 на кампанию, 20 пилотов по 10–200. Не путать остаток env после пилотов с окончательным остатком после финальных кампаний.

`environment.py`, `mock_environment.py`, `scoring_core.py`, `local_eval.py`, `make_submission.py`, `agent_template.py`, `PARTICIPANT_GUIDE.*` и исходные CSV — материалы организаторов; хранить неизменными. SHA256 в `docs/organizer_manifest.json`. Не читать внутренности скрытой модели из агента. Не импортировать mock_environment/local_eval/scoring internals в agent/strategy/research. Проверочные инструменты в tools/tests могут использовать официальный локальный оценщик.

История переключений не содержит всех получателей предложений, поэтому частоты переходов не являются измеренной вероятностью конверсии. Не подгонять стратегию к значениям мока. LLM необязательна; ключи/купоны не коммитить. Не активировать кредиты и не создавать платные инстансы без отдельного поручения.

## Готовность

Запустить `python local_eval.py`, `python local_eval.py --runs 10`, `python make_submission.py`, `python -m unittest discover -s tests -v`. Для изменений документации без кода достаточно проверки ссылок/команд. Не заявлять о проверках, которые не выполнены. Финальный ответ: что изменено, что проверено, что осталось, ветка/PR. Записывать наблюдаемые числа как результат мока, не как обещание судейского результата.
