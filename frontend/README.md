# Frontend — Манс

Один dashboard на HTML/CSS/JavaScript без сборщика и внешних библиотек. Данные поступают только с API; встроенных fixtures и ключей нет.

Рекомендуемый запуск из корня: `python run.py`, затем http://127.0.0.1:8000/ — dashboard. `/docs` — документация, не интерфейс. Отдельный сервер frontend не нужен. API автоматически использует origin страницы; на компьютере коллеги не подставляется его localhost.

Для отдельной разработки допустим `python -m http.server 5173 --bind 127.0.0.1 --directory frontend` вместе с backend на 8000. В этом режиме UI использует тот же hostname, порт 8000. В настройках можно явно выбрать другой API или сбросить адрес.

Сценарий: выберите инцидент → запустите анализ → укажите бюджет → выберите доступное решение → подтвердите создание work order. Изменение бюджета автоматически пересчитывает варианты с задержкой 450 мс. Пока расчёт не актуален, выбор решения сбрасывается. Схема вышек строится по lat/lon, не является географической картой и не вычисляет покрытие.

Ответы GET /towers и /incidents читаются из items, GET /incidents/{id} — из incident. Используются POST /analyze, /simulate, /action по docs/API_CONTRACT.md. API-контракт не изменён. Все числа сети, цены и прогнозы приходят с backend. Ошибки API выводятся пользователю; автоматических повторов POST /action нет.

Проверено с настоящим FastAPI из main: анализ INC-1042 (agent_mode=demo, 6 инструментов), бюджет 20 млн ₸, Upgrade за 12 млн ₸, создание WO-8821 и чтение через GET /work-orders/{id} после перезапуска backend. Пустой результат анализа и 404 неизвестного заказа обработаны. Отображаются режим агента и журнал. Реальный OpenAI с ключом не вызывался.

Сохранённый заказ можно найти по номеру внизу страницы. Desktop просмотрен в браузере; ширина 390 px проверена без горизонтального переполнения. Синтаксис JavaScript проверен. Защита от устаревшей симуляции дополнительно проверялась на задержанном тестовом ответе API.

## Упрощённый интерфейс

Три шага: выбрать инцидент, сравнить решения, создать заказ. Поиск и фильтры работают локально по полученным данным (приоритет, статус, район, причина). Изменение фильтра не заменяет выбранный инцидент: его номер всегда показан в диагностике. Сводка считает всю сеть, независимо от фильтра списка.

Бюджет принимает целые неотрицательные KZT с пробелами, форматируется при выходе из поля; есть кнопки 10/20/50 млн. Смена бюджета сразу удаляет старые сравнение, выбор и прогноз, затем запускает новый расчёт. Сравнение показывает все варианты, в том числе недоступные. Подсказка и метки используют цену и expected_load_pct из API; выбор остаётся за человеком. Прирост покрытия не преобразуется в радиус без определённых backend допущений.

Проверено после обновления: реальный FastAPI из main с 35-секундным лимитом агента; demo-анализ, сравнение 12/18/40 млн, WO-8822 и его чтение, бюджет 2 000 и нехватка 11 998 000, фильтр приоритета, пустой поиск, сброс выбора при смене бюджета, пустой анализ. На 390 px таблица прокручивается внутри своего блока, страница не переполняется. История нагрузки, confidence и несуществующие статусы заказа не генерируются. Запуск и контракт прежние.

## Настройки, ссылки и карта

Бюджет, поиск, фильтры и выбранный инцидент сохраняются локально в браузере по ключу `network-dashboard:v1:<API URL>`. Адрес API хранится отдельно в `network-dashboard:api:v1` после явного подключения. В localStorage не сохраняются жалобы, ответы анализа, work orders или выбранное решение. При перезагрузке API перечитывается и симуляция выполняется заново. Блокировка или повреждение localStorage не мешает работе. Значения удалённых из данных фильтров сбрасываются.

Ссылка на инцидент содержит только `?incident=<id>` и якорь страницы. Этот ID имеет приоритет над локальным выбором; если его нет в API, dashboard сообщает об этом и не подставляет другой инцидент. Ссылка копируется в разделе диагностики; при недоступном буфере выделяется поле для ручного копирования. Для совместной работы нужен общий адрес frontend и одинаковая настройка API; localhost не доступен коллегам с другого компьютера.

В карте доступен выбор вышки, число её инцидентов, координаты и переход в диагностику конкретного инцидента. Просмотр вышки сам по себе не меняет выбранный инцидент и заказ. Географическая карта выбранной вышки открывается в новой вкладке [OpenStreetMap](https://www.openstreetmap.org/); все координаты берутся из `/towers`, ключ карты не нужен. Это отдельная внешняя карта одной вышки, не слой всей сети. В dashboard остаётся локальная схема всех вышек; её работа не зависит от внешнего сервиса. В API ожидаются числовые `id`, `lat`, `lon`, а связь с инцидентами задаётся через `tower_id`. Неизвестные/неподдерживаемые координаты не передаются карте (для карты широта в пределах ±85°, долгота ±180°). Никаких расчётов зон покрытия по картинке нет.

Подсказки сравнения показывают минимальную стоимость, минимальный срок и минимальную прогнозную нагрузку среди доступных решений в бюджете. Равные результаты перечисляются вместе. Поля: `available`, `cost_kzt`, `installation_days`, `expected_load_pct`; числа не генерируются frontend.

Индикатор подключения — состояние последнего запроса, без фонового health polling. Время свежести — последняя полная загрузка `/towers` + `/incidents` в браузер, а не timestamp измерения; через 5 минут появляется предложение обновить. Кнопка обновления перечитывает сеть и выбранный инцидент. Повтора POST /action нет; при сомнительном результате нужно проверить сервер до ручной повторной попытки.

## Повторяемая проверка

Для запуска приложения Node.js не нужен. Для регрессионных проверок нужен Node.js 18+ без npm-зависимостей:

```sh
node --check frontend/app.js
node --test frontend/tests/dashboard.test.cjs
```

Тесты используют небольшой DOM-адаптер и управляемые ответы API; они проверяют состояние приложения и асинхронные сценарии, не заменяют браузерную проверку интерфейса. Девять тестов проходят. Интеграция в браузере на текущем FastAPI: demo-анализ INC-1042 → бюджет 20 млн → upgrade 12 млн → WO-8825 → поиск этого заказа. Также проверены сохранение настроек после reload, ссылка на другой инцидент, копирование, карта → диагностика и мобильная ширина 390 px с открытым сравнением без переполнения. Географическая карта доступна отдельной страницей; встроенный iframe не используется. Реальный OpenAI и полные данные команды не проверены.


## Финальная интеграция

Подключены данные Абыла из main 6de9d59. `POST /analyze` передаёт выбранный incident_id, если район не изменён. Повторное подтверждение показывает сохранённый заказ при `created: false`; список заказов выбранного инцидента читается через `GET /work-orders`. Адрес API хранится по origin страницы (v2), чтобы старый localhost не перехватывал общий адрес. Старые заметки выше описывают предыдущие прогоны; актуальные результаты — в STATUS.md.
